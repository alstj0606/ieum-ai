# 카드 계약·관련성·버튼·날짜 수정 (2026-11-10)

## KeyError: 확인한 사실과 미확인 원인

조사 기준 main은 PR #12 병합 커밋 `d68ddf3`이다. 해당 커밋의 카드 필드와 `activity_facts`를 비교하면 공식 데이터 10건에서 필수 키 누락이 없다. 사용자 로그는 KeyError의 실제 키 문자열을 포함하지 않으므로 배포에서 빠진 키를 확정할 수 없다. Community Cloud의 실제 checkout과 메모리 모듈 버전도 직접 확인하지 못했다.

반면 PR #10 병합 당시(`4db9ebf`)의 포맷터와 PR #12 카드를 조합하면 **다음 접수 예정일**이 첫 누락 키로 재현된다. **준비물**도 누락되며 접수 기간은 ISO 원문이다. 이는 두 배포 증상과 일치하는 재현 가능한 버전 혼재 시나리오이며, 실제 배포 원인을 확정한 것은 아니다. 틸드 이스케이프보다 앞선 `facts[key]` 접근에서 오류가 발생하는 구조다.

### 구조 수정

- `services/card_view.py`에 `CARD_FIELDS`, `DETAIL_FIELDS`, `REQUIRED_KEYS` 계약을 두고 app.py가 같은 정의를 사용한다. 카드·대안 미리보기는 모두 `card_facts`를 통과한다.
- 생산자가 필드를 누락하면 `card_contract_missing_fields`와 **필드 이름만** 개발 로그에 남긴다. 프로그램명·사용자 질문·API 오류 원문·키는 기록하지 않는다. 테스트는 정상 생산자가 계약을 모두 충족하는지도 별도로 검사하므로 기본값으로 구조 불일치를 감추지 않는다.
- 누락/None 값은 안전한 문구로 정규화한다. 원본 행의 필드 누락/None도 표시 함수에서 처리하며, 잘못된 상태는 접수 미확인으로 내린다. 원본 JSON 로더의 엄격한 검증은 유지한다.
- 접수 기간과 다음 예정일은 오래된 포맷터를 신뢰하지 않고 원본 접수 필드에서 재계산한다. 구버전 반환값과 None 값을 주입해도 모든 카드가 중단 없이 렌더링되는지 검사한다.

## 관련성 정렬

기존 대안 정렬은 `available`을 먼저 보아 접수 가능한 파크골프가 마감된 슬로우조깅보다 앞섰다. 이제 `alternative_rank`가 아래 순서의 튜플을 반환한다.

1. 직접 일치(0) → 유사 활동(1) → 다른 대안(2)
2. 명시된 목적, 명시된 가벼운 운동 선호에 대한 속도 변화 주의, 움직임 방식의 공통점, 이동을 줄이고 싶다는 경우 장비/시설 확인 부담
3. 위 관련성이 같은 경우 접수 가능 표시, 마지막으로 편집된 관계표 순서

걷기와 슬로우조깅은 보행이라는 움직임이 이어지는 유사 활동이며, 파크골프는 도구를 쓰는 다른 대안으로 분리한다. 강서구 실제 자료에서는 **마감된 슬로우조깅 → 접수 가능 표시 파크골프** 순서가 된다. 마감 자료를 신청 가능하다고 승격하지 않으며 신청 안내 버튼도 없다. 정확한 걷기 프로그램이 있으면 원래 검색 결과가 우선이고, 정확한 참고 카드도 유사 활동 목록보다 먼저 표시한다.

이 분류는 일반 활동 방식의 편집된 비교 규칙이며 실제 강도·건강 적합성·거리·시설 접근성을 검증한 점수가 아니다. 실제 운동 강도는 확인 필요로 안내한다. 나이만으로 운동 능력·강도 선호를 만들지 않는다. 명시적 ‘가벼운/가볍게/천천히’ 등의 선호는 `effort_preference`로 누적한다. Gemini 추출 스키마도 같은 필드를 받되 모델·API 설정은 바꾸지 않았다.

연령·초보·거주 자격·시간·예산 등 기존 필터를 먼저 적용한다. 부적합 활동을 순위만 낮춰 끼워 넣거나 예산/시간을 몰래 완화하지 않는다. 실제 프로그램명·비용·시설을 생성하지 않는다.

## 공통 버튼

활동 선택·대안 선택·지역 동의·시간 선택·다시 찾기에는 공통 `choice_button` 렌더러와 기본 primary 버튼을 사용한다. 일반 동작 버튼도 공통 `.stButton`/`.stFormSubmitButton` 스타일로 고대비 색상, 굵은 글씨, 64px 높이, 여백을 적용한다. 비활성 버튼은 비활성 상태를 유지한다. 펼침 영역은 두꺼운 테두리와 별도 배경, 기본 펼침 화살표로 구분한다. 신청 안내 버튼은 긴 주의사항 펼침 안에 숨기지 않고 핵심 정보 바로 아래에 둔다. 마이크·전송 컨트롤은 기존 기능과 스타일을 유지한다.

빠른 클릭이 지연 스크롤 때문에 사라지지 않도록 답변 앵커가 처음 나타난 시점의 조작 번호를 기록한다. 이후 조작이 있으면 지연 스크롤을 취소하고 이전 답변의 타이머가 최신 답변을 덮지 못하게 한다. 저장하는 것은 숫자와 UI 앵커 ID뿐이며 입력/음성 내용은 수집하지 않는다. 가상 키보드 크기 변경 시에도 최신 답변 복원을 제한적으로 재시도한다. 기존 STT/TTS 동작은 바꾸지 않는다.

## 날짜 표시

`services/date_display.py`를 공통 표시 경계로 사용한다. 원본 JSON과 공식 링크는 변경하지 않는다.

- 접수 기간: `2026.08.18 ~ 08.21`, 연도가 바뀌면 종료 연도도 표시.
- 접수 시작/마감 시각: 필요 정보로 별도 표시, 한국 시간으로 변환.
- 운영 설명·확인일·비용 참고 등 표시 텍스트의 날짜도 점 형식으로 정리. 잘못된 날짜는 공식 자료 확인 필요.
- 잘못된 형식, 시간대 없는 접수 일시, 시작/종료 역전은 안전한 안내. 표시 오류 때문에 앱 전체가 중단되지 않음.
- 다음 예정일은 공식 접수 기간이 미래이고 기존 안전한 상태 판단도 upcoming인 경우에만 표시. 과거·마감·미확인에서는 **다음 접수 일정 미정**.
