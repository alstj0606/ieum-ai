# 활동 추천 → 시설/프로그램 안내 흐름

작업일: 2026-11-09 (한국 시간). 최신 main `b0e0f1a`(PR #8 병합 후)에서 `feat/activity-guidance-flow` 생성.

## 이번 구현

기존 앱은 모든 요청을 공식 프로그램의 정확 일치 검색에 가깝게 처리했다. 이번에는 ‘무엇을 할지 제안’과 ‘실제로 어디서/언제 신청할지 확인’을 분리했다. Gemini 오류 수정이나 새 데이터 조사 작업은 아니다.

- Gemini 스키마에 recommend_activity/find_facility/search_program/change_condition 의도와 명시적 이동 선호 mobility를 추가했다. 기존 search/apply/조건·해제·선택 계약과 로컬 검증도 유지한다.
- Gemini가 의도/조건을 추출하고, 프로그램 사실·추천 문구·분기·후속 질문은 Python이 결정한다. API 실패/키 없음일 때도 같은 기본 흐름을 제한적인 키워드 규칙으로 제공한다. 모델·API 경로·현재 오류 진단 체계는 그대로다.
- ‘노인이 할 수 있는 운동’은 숫자 나이나 건강 상태를 생성하지 않고 일반 활동을 제안한다. Gemini가 이 표현만으로 숫자 나이를 반환해도 직접 ‘숫자+세/살’로 말하지 않았다면 새 나이 조건으로 사용하지 않는다.
- ‘근처 수영장’은 지역이 없으면 한 가지 지역 질문부터 한다. 현재 위치·거리·GPS를 추정하지 않는다. 기존 지역이 있으면 반복해서 묻지 않는다. 지역 무관 답변은 명시적인 강서구 선택 또는 일반 활동으로 이어가며 같은 질문을 반복하지 않는다.
- ‘강서구에서 수영 배우고 싶어’는 실제 프로그램 검색을 유지한다. 결과가 없으면 기존 no_match/마감/자격/미확인 구분을 유지하면서 관련 일반 제안·시간 조건 풀기 버튼을 제공한다. 같은 조건 재검색 시 반복 안내 대신 새 자료가 없다는 설명과 다음 행동을 제공한다.

## 일반 활동과 개인 조건

`services/activity_guidance.py`의 사전 작성 목록은 걷기, 수중운동, 체조, 파크골프, 수영 입문, 그림·만들기, 식물 가꾸기, 공연, 인문학이다. **실제 모집 프로그램 데이터가 아니다.** 시설명·요금·일정·접수 여부를 넣지 않는다.

일반 추천은 최대 3개이며 활동/관심 태그, 관련 활동, 교류 목적, 무료 선호, 이동을 줄이는 선호 등을 기준으로 결정적으로 정렬한다. 이동을 줄이고 싶다는 경우 가까운 공간에서 해볼 방식을 생각할 수 있는 일반 활동을 우선하되 실제 시설 거리나 접근성이 확인됐다고 말하지 않는다. 한 가지뿐이면 억지로 3개를 채우지 않는다.

나이는 일반 활동 가능 여부나 건강 상태 판단에 쓰지 않는다. 실제 프로그램에 명시된 나이·성별·초보 자격은 기존 추천 서비스에서 별도로 검증한다. 시간·예산·나이·이동 선호를 기억하고 설명하되, 일반 제안의 실제 운영시간·참가비가 확정된 것으로 표현하지 않는다.

버튼으로 고른 활동은 현재 제안 목록에 있는 ID만 허용한다. 지역·시간·예산·나이·이동 등 개인 조건을 유지하고 이전 활동 종류·분류·관심 제한·학습 목적·초보 조건은 새 선택이 막히지 않도록 정리한다. 그 뒤 공식 자료 검색으로 이어가며 지역이나 양수 예산 단위처럼 필요한 정보만 한 번에 하나씩 묻는다. 활동 선택 버튼은 고정된 서버 동작이므로 Gemini 실패 때도 추가 API 호출 없이 동작한다.

## 시설과 실제 프로그램의 경계

실제 프로그램 검색/참여 자격/비용 0과 null 구분/접수 상태 계산/공식 신청 안내는 기존 모듈과 data/activities.json 10건을 그대로 사용한다. 일반 활동 제안은 실제 카드와 다른 제목으로 표시한다.

시설은 공식 프로그램 자료에 명시된 facility_name/address/source_url/verified_at만 뽑아 중복을 제거한다. 수영장은 수영/아쿠아로빅 자료에 나온 관련 시설만 대상으로 한다. 시설 운영 현황을 새로 조사한 디렉터리가 아니다. 근거 프로그램의 이름·접수 상태도 함께 표시하며 현재 시설 운영·요금·거리·강좌·접근성은 별도 확인이라고 안내한다. 오래되거나 모집 미확인 자료로 현재 신청 가능을 보장하지 않는다.

추천 아이디어나 시설에서 ‘이거 어떻게 신청해?’라고 해도 실제 프로그램이 없으면 신청 완료나 임의 절차를 만들지 않는다. 활동을 골라 검증된 프로그램부터 찾도록 안내한다. 실제 결과가 있으면 기존 공식 신청 절차/링크를 안내하고 예약·결제·신청 완료로 처리하지 않는다.

공식 데이터 지원 범위는 서울 강서구다. 다른 지역의 위치를 추정하거나 실시간 검색을 했다고 말하지 않는다. 요청 지역 조건은 보존하며 사용자가 ‘서울 강서구 자료로 찾기’를 선택해야 바뀐다. 확장은 REGION_SCOPES 설정과 검증된 지역 데이터, 시설 분류·일반 활동 목록을 늘리는 방식으로 할 수 있다. 현재의 지역 범위를 자동으로 확대한 것은 아니다.

## 화면·음성·오류

단일 채팅과 마이크/전송 버튼은 유지했다. 최신 답변 안에 일반 활동 선택 버튼, 실제 프로그램 카드 또는 근거가 있는 시설 카드를 표시한다. 선택 후 다음 사용자/답변 말풍선으로 자연스럽게 이어간다.

API 실패는 ‘Gemini 연결을 이용하지 못해 기본 규칙으로 안내’라는 짧은 안내로 표시한다. 성공한 척하지 않으며 고정 진단 코드는 보조 메뉴의 ‘연결 상태 확인’에서 계속 볼 수 있다. 기존 모델/생성 진단도 보조 메뉴에 유지했다.

TTS는 화면의 일반 제안 제목/이유를 읽을 때 ‘일반 활동이며 실제 강좌 아님’을 포함하고, 시설도 현재 이용 가능을 보장하지 않는 문구를 함께 읽는다. 기존 OpenAI STT/TTS 연결·인식문 수정·재녹음·재생/중지는 유지한다. 무료 브라우저 음성으로 교체하지 않았다.

브라우저 테스트에서 긴 대화 뒤 메뉴를 빠르게 열면 최신 답변 자동 스크롤이 메뉴 위치를 바꾸는 경로를 발견했다. 메뉴가 열려 있거나 새 사용자 조작이 있을 때 예약된 자동 스크롤을 멈추고 메뉴에서 검색/업로드/예시/초기화를 실행한 경우에만 자동으로 메뉴를 닫도록 정리했다. 마이크 DOM/전송 스타일은 변경하지 않았다.

## 검증 범위

- unittest **100개**: 기존 83개 중 추천 요청이 실제 프로그램 즉시 검색 대신 일반 제안으로 바뀌는 기대값을 갱신했다. 일반 추천/근처 지역 질문/수영 0건/다른 운동/오전·조건 변경/선택과 프로필 유지/명시적 관심·이동·나이/지원 외 지역/실패 대체/잘못 생성한 나이·지역 제거/일반 제안 신청 제한/명시적 시간 완화/지역 무관 응답/Gemini 정상 의도·조건과 UI 동작 등 17개를 추가했다.
- Chromium/Playwright **16개 흐름**: 기존 13개를 새 안내와 진단 메뉴 위치에 맞게 갱신하고 320/390/768px 각 화면의 일반 추천→활동 선택→미확인 자료→근처 수영장→지역 질문→시설 근거→구체적 수영 0건→다른 운동→시간 변경 흐름을 추가했다. 큰 선택 버튼·가로 넘침, 기존 공식 신청/마이크 전환/음성 모의/권한·재생 실패/진단 보존도 검사한다.
- 실제 Gemini/OpenAI 실호출, 한국어 인식·추천 품질의 사용자 평가, iPad/iPhone Safari·Android Chrome 실기기 및 이 변경의 Community Cloud 배포는 미검증이다. 모델 오류 자체가 해결됐다고 주장하지 않는다.
- 프로그램/시설 출처를 새로 수집하거나 재검증하지 않았다. 기존 공식 자료와 기록된 확인일을 그대로 보존했다. 일반 활동 목록은 출처가 검증된 모집 데이터가 아니라 사전 작성된 제안이다.

## 미구현

실시간 웹/지도 검색, GPS·거리 정렬, 실제 시설 운영/잔여석 확인, 타 지역 공식 자료, 자동 신청/예약/결제, 의료·재활 적합성 평가, 모든 건강/이동/예산 조건에 대한 검증된 매칭은 없다. 기본 규칙은 표현 범위가 제한되며 일반 제안만으로 실제 참여 가능을 판단할 수 없다.
