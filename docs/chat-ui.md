## 사용 흐름

- 첫 화면은 이음 AI, 짧은 인사, 하나의 고정 채팅 입력창과 작은 보조 메뉴다.
- 빈 입력창에는 큰 마이크(80×80px), 글을 쓰면 큰 전송 버튼을 보여준다. 글이 있을 때 마이크는 숨기고 비활성화한다. 작은 ‘음성 입력으로 돌아가기’ 버튼은 글을 비우고 마이크에 초점만 옮긴다. 녹음은 다시 명시적으로 눌러야 시작한다.
- 녹음 중 ‘🔴 듣고 있어요’, ‘말하기 끝내기’, ‘취소’를 표시한다. 종료 후 native Streamlit 채팅 위젯이 오디오를 제출하며 STT→LLM 조건 이해→공식 JSON 검색→대화 답변으로 연결한다.
- **침묵 감지/자동 녹음 종료는 구현하지 않았다.** 1분은 서버 검증 제한이며 브라우저가 자동으로 녹음을 끊는다는 의미가 아니다.
- 음성 질문 뒤 화면과 같은 사실 원문으로 TTS를 한 번 생성하고 자동 재생을 시도한다. 자동 재생 성공은 가정하지 않는다. 큰 ‘답변 듣기’는 준비된 오디오를 직접 사용자 조작으로 재생하며 재생 거부 메시지를 표시한다. 재생기와 중지 버튼도 제공한다.
- 인식문은 사용자 말풍선에 표시한다. ‘음성인식이 다르게 되었나요?’에서 수정해서 다시 질문하거나 입력창의 마이크로 다시 말한다. 기존 조건은 유지된다. 완전히 잘못 이해한 대화를 버리려면 보조 메뉴의 초기화를 사용한다.
- ‘다시 말해줘’는 같은 답변, ‘천천히 알려줘’는 같은 답변을 속도 0.7로 다시 안내한다. 사실이나 조건을 새로 생성하지 않는다. 실제 한국어 발음/속도의 적절성은 미검증이다.
- ‘신청 방법 알려줘’는 기존 대화의 선택 활동과 공식 신청 안내를 이용한다. 자동 예약·결제·신청은 하지 않는다.

## 대화와 카드

각 사용자 질문과 AI 답변은 한 대화 목록에 순서대로 표시한다. 해당 답변 안에 최대 3개 카드가 들어가며 별도 결과 구역은 없다. 이전 답변의 카드는 그 당시 검색 결과의 사본이다. 이전 카드에서는 신청 동작을 제공하지 않으며 최신 답변에서 다시 조회한다.

카드 앞면에는 이름·장소·시간·비용·접수 상태만 표시한다. 상세에는 대상·주소·확인 메모·준비물 확인 필요 안내·출처·공식 링크·신청 방법이 있다. JSON에 별도 준비물 필드가 없으므로 생성하지 않으며 원문의 확인 메모도 그대로 표시한다. 비용 0/null은 기존 표시 함수를 그대로 이용한다.

전화 링크는 검증된 JSON의 `registration_method`에 실제로 있는 하이픈 형식 전화번호만 연결한다. 문의 전화가 신청 전화라는 뜻으로 바꾸지 않는다. 마감·자격 불일치·모집 미확인·데이터 부족 안내는 기존 Python 추천 서비스를 유지한다.

최신 답변의 시작 위치로 이동한다. 입력창은 Streamlit 기본 고정 채팅 위젯을 사용하며, 가상 키보드의 visualViewport 크기 변경 때 최신 답변 위치를 다시 보여주는 보조 처리를 한다. 실제 iOS/Android 키보드 동작은 실기기 확인이 필요하다.

‘＋ 보조 메뉴’에 AI 도움 없이 검색, 음성파일 업로드, 가상 수영 예시, 이용 설명, 초기화를 넣었다. 사진/문서 처리 기능은 표시하지 않는다. 시연 데이터는 독립 말풍선이며 기존 공식 검색 조건을 덮어쓰지 않는다.

## 기술과 개인정보

- 추가 Python/JS 패키지 없음. 고정된 Streamlit 1.66.1의 `st.chat_input(accept_audio=True)`를 사용한다.
- `ui/chat.css`, `ui/chat.js`: 버튼 크기/마이크·전송 전환/한국어 접근성 이름/키보드 화면 보조. `ui/player.html`: 준비된 오디오의 직접 재생과 실패 안내.
- Streamlit 기본 버튼 이름이 영어이므로 고정 JS의 MutationObserver로 마이크·전송·종료·취소를 한국어로 바꾼다. JS가 실행되지 않거나 Streamlit DOM이 변경되면 한국어 이름/모양 보정이 적용되지 않을 수 있다. 버전 업그레이드 시 브라우저 회귀 검사가 필수다.
- `st.html(unsafe_allow_javascript=True)`에는 저장소의 고정 코드와 서버가 생성한 정수 대화 번호만 전달한다. 사용자 질문·모델 응답·키·URL은 스크립트/HTML에 삽입하지 않는다. 사용자/공식 정보는 기본 Streamlit 텍스트로 표시한다.
- 키는 기존 환경변수/Secrets에서만 읽는다. 새 설정 항목은 없다. 녹음과 생성 음성은 세션 메모리에서만 사용하며 파일로 기록하거나 로그로 출력하지 않는다. 음성·환경 파일 ignore 규칙은 유지한다.
- UI 대화는 최대 20회, LLM 대화 이력도 기존 제한을 유지한다. 새 답변에서 이전 재생 데이터를 지운다. 파일 업로드는 내용 해시로 재실행 중 중복 전송을 막는다.
- 공식 데이터 10건, 출처, 기존 검색·추천·조건 추출·API 모델 설정은 변경하지 않았다. `services/voice.py`는 느린 TTS 속도 선택만 추가했다.

## 검증과 한계

- unittest 55개 통과: main의 50개 항목 중 UI 진입/표시 방식 6개를 새 채팅 화면에 맞게 갱신하고 자동 음성 검색·수정/느린 재안내, 대화→추가 질문→카드→신청 안내, TTS 속도 검증을 추가했다.
- Chromium/Playwright 9개 흐름: 320/390/768px의 채팅/후속 질문/카드 안 신청 안내/한국어 버튼 이름/마이크·전송 전환/가로 넘침/작아진 화면의 입력창과 최신 답변 3개, 합성 마이크+Space 종료→모의 STT→자동 검색/TTS/직접 재생·중지/수정 1개, 권한 거부·장치 실패·미디어 API 미지원 3개, 재생 거부 후 텍스트 대화 1개, 보조 메뉴의 파일 업로드→자동 검색 1개.
- 모의 STT는 고정 문장, 모의 TTS는 시험용 톤이다. 실제 AI 추론·한국어/사투리 인식·음질 검증이 아니다.
- 실제 OpenAI 호출, iPhone/iPad Safari, Android Chrome, VoiceOver/TalkBack, 실물 키보드/마이크/스피커, Streamlit Community Cloud 배포는 미검증이다. 화면 크기 축소는 실제 가상 키보드 검증을 대신하지 않는다.
- 브라우저 자동 재생은 보장하지 않는다. 기본 오디오 재생기 ▶와 텍스트가 항상 대안이다. 실제 배포에서는 HTTPS 앱 주소를 직접 열고 마이크 허용/거부, 전송 전환, 후속 질문, 인식문 수정, 자동/직접 재생과 중지를 확인한다.
- API 키/모델 설정은 기존 docs/ai-voice.md를 따른다. 실제 키로 접근 권한·요금·STT/TTS를 소수 호출하여 검증해야 한다. TTS 모델의 2027-01-06 종료 예정도 기존 문서에서 확인한다.
