# 대화 연속성 수정과 단계별 신청 도우미 MVP

## 확인한 원인

기준 main `924f087`(PR #15 병합)에서 `st.session_state.dialog`와 `turns`는 재실행 시 이미 있는 값을 보존합니다. 로컬 AppTest에서도 프로필은 유지됐습니다. 따라서 실제 iPad에서 세션이 초기화됐다고 확정하지 않습니다. Cloud 재연결/브라우저 재접속 로그를 확인한 것은 아닙니다.

실제 코드 경로는 `send → handle_turn → _search → prepare_view → 카드 전체 렌더링`입니다. 후속 시간 발화도 `_search`로 들어가 `selected_id=None`을 설정했고, 이전 결과와 비교하는 계층이 없었습니다. 오후 선호는 필수가 아니므로 후보가 바뀌지 않는 것이 정상일 수 있지만, 같은 첫 소개와 카드를 반복해 새 대화처럼 보였습니다. 공식 자료에 남은 신청 가능 체육 활동이 주로 파크골프 시설이라는 데이터 한계도 있습니다. 가벼운 운동에 적합한 강습으로 확정한 결과는 아닙니다.

`continuity.py`가 기존/새 조건과 후보·순서를 비교합니다. 조건만 바뀐 턴에는 추가/해제/유지 조건, 동일 결과의 이유 또는 제외/추가/순서·상태 변화 안내를 표시합니다. 같은 카드의 전체 재출력 대신 짧은 목록과 다시 보기 버튼을 제공합니다. 시간 설명은 `schedule.time_slots`만 사용합니다. 실제 자료의 파크골프에는 오후 회차가 있지만 잔여석·회차별 자격은 별도 확인해야 합니다. 시간 미확인 fixture에서는 오후 운영을 주장하지 않습니다. 결과에 남은 선택 프로그램과 신청 진행 단계는 유지하고 다른 프로그램이나 필수 조건 변경으로 빠지면 안내 상태도 해제합니다. Gemini 모의 성공/실패에 공통으로 적용하며 실패 안내는 숨기지 않습니다.

## 단계별 안내

우선 대상: **서남센터 파크골프장(18홀)**. 공식 상세와 공통 매뉴얼을 결합한 안내이며 로그인 이후 실환경 종단 검증은 아닙니다.

1. 공식 상세의 이용 조건 확인.
2. 공식 로그인(처음 이용 시 통합회원 가입·본인확인이 필요함을 안내).
3. 예약하기에서 날짜·회차·인원 선택.
4. 공식 화면의 필수 항목과 조건을 확인한 뒤 직접 예약하기.
5. 나의 예약내역에서 실제 처리 상태와 유료 결제 안내를 직접 확인.

로그인 이후 미확인 개별 필드명·버튼 위치·결제 버튼·완료 화면을 만들지 않습니다. 공식 링크와 단계별 근거 링크를 제공하며 한 번에 한 단계만 표시합니다. 실제 사이트와 안내가 다르면 공식 안내·문의처를 이용해야 합니다. 다음/이전/다시 설명/이어보기는 이음 AI의 안내 위치만 바꿉니다. 마지막 버튼도 ‘안내를 끝까지 확인했어요’이며 예약 완료 상태를 생성하지 않습니다. 비밀번호·인증번호·개인정보는 이음 AI에 입력하지 말라고 안내합니다.

접수 마감·종료 시 예약 단계 대신 다음 모집 확인 안내로 전환하며 다음 날짜는 추정하지 않습니다. 미확인/접수 예정/현장 선착순은 현재 예약 가능으로 표시하지 않습니다. 검증되지 않은 프로그램은 임의의 단계 대신 절차 미확인과 공식 확인 방법만 안내합니다. 문의 전화와 전화 신청은 별개이며 현재 신규 검증 자료 중 전화 신청이 확인된 것은 없습니다. 전화/방문 방식은 각각 독립적으로 표시하고 확인하지 못한 항목은 확인 필요로 둡니다.

## 세션과 모바일

선택 프로그램 ID·안내 모드·단계·안내 열람 여부만 현재 세션에 저장합니다. 사용자 계정·영구 저장·신청서 전송을 추가하지 않았습니다. 단계가 바뀔 때 기존 최신 답변 시작 스크롤 제어를 재사용합니다. 이전 단계 기록은 대화에 요약해 보존합니다. 큰 공통 버튼과 한국어 텍스트를 사용하며 CSS/JS 내부 DOM 조작을 추가하지 않았습니다. 새 모듈을 서비스에서 불러오는 import 계약과 앱 시작을 자동 검사합니다.

## 검증 방법과 한계

`python -m unittest discover -s tests`와 로컬 Streamlit AppTest로 조건/선택/재실행, 새 조건 설명, Gemini 모의 성공·실패, 단계 이동/초기화, 접수 재검사, 문의·방문 미확인, 서비스 import 계약을 검사합니다. `node tests/browser_continuity_helper.cjs`는 320/390/768px에서 키 없는 앱과 모의 Gemini 앱의 실제 UI 흐름을 검사합니다. 기존 추천·카드·음성 모의 브라우저 검사도 유지합니다.

실제 Gemini/OpenAI API, iPad/iPhone Safari·Android 실기기, Streamlit Community Cloud 배포, 외부 로그인/신청/결제는 미검증입니다. 기존 수록 자료와 확인된 공통 문서 기반 안내만으로 실제 신청 완료를 보장하지 않습니다. 후속으로 운영자가 실제 로그인 화면의 변경 여부를 점검하고, 새 공식 모집 자료 및 추가 프로그램별 절차를 검증해 늘려야 합니다.

## 변경 파일

- `app.py`: 중복 카드 축약, 다시 보기/이어보기, 단계별 패널·공식 링크·문의/방문 정보와 해당 단계 TTS.
- `services/dialogue.py`: 공통 후속 처리 경계, 신청 안내 연결, 선택/진행 보존, 수동 검색 초기화.
- `services/continuity.py`: 조건·결과 차이와 설명, 이전 추천/선택/질문 맥락 보존.
- `services/application_helper.py`: 출처가 있는 안내 로딩, 접수·자격 재확인, 단계 이동, 완료 오인 방지.
- `data/application_guides.json`: 기존 활동 3건의 보조 신청 근거. 온라인 상세 도우미 대상은 1건.
- `README.md`, `docs/continuity-application-helper.md`: 현재 기능·출처·미확인 범위.
- `tests/test_continuity_helper.py`, `tests/test_app.py`: 자동/앱 시작·재실행·음성 문구 회귀 검사.
- `tests/browser_continuity_helper.cjs`: 새로운 모바일 흐름.
- `tests/browser_personalization.cjs`, `tests/browser_trusted_flow.cjs`: 동일 결과 축약과 기존 스크롤 회귀 검사 갱신.
- `tests/browser_alternatives.cjs`, `tests/browser_card_contract.cjs`, `tests/browser_smoke.cjs`: 신청 버튼의 명확한 새 문구 반영.
- `tests/mock_voice_server.py`: 후속 발화의 모의 API 실패 시나리오 추가. 요청 본문·음성·인증 헤더를 기록하지 않음.

- 전체 자동 테스트 **173개 통과**(기존 149개 + 신규 24개). AppTest로 실제 앱 시작·rerun과 채팅 신청 진입·단계 보존까지 검사했습니다.
- Chromium **41개 흐름 통과**: 기존 35개(화면 흐름 변경에 맞게 갱신) + 새 도우미 6개(320/390/768px × 키 없음/모의 Gemini). 공식 카드 10건, 추천 순서, 최신 안내 위치, 기존 음성 실패 후 텍스트 이용을 포함합니다.
- Python 문법 검사와 `git diff --check` 통과. 공식 데이터·Gemini 설정·음성 모듈·CSS/JS·의존성 파일 변경 없음.
- 초기 브라우저 실행에서 모의 404 진단 표시 대기 한 건이 시간 초과됐습니다. 새 세션에서 예상 진단을 확인했고, 최종 단독 smoke 16개는 전부 통과했습니다. 최초 시간 초과의 원인은 확정하지 않았습니다.
