## 작업 기반과 구조

PR #16은 main `4965586`에 병합된 것을 GitHub API와 Git 기록으로 확인했습니다. 해당 main에서 `feat/seongsan-application-mvp`를 생성했습니다. 임의 병합은 하지 않았습니다.

- `app.py`는 기본 성산 화면과 기존 강서구 화면을 분리하는 진입점입니다.
- 기존 앱 본문은 `gangseo_app.py`로 이동했고 돌아가기 버튼만 추가했습니다. 공식 활동 10건, 개인화/대안/인접 동의/카드/신청 도우미/음성/설정은 보존합니다.
- `ui/seongsan_app.py`는 첫 4개 행동과 현재 신청 단계 한 개를 표시합니다. 기관 안내와 강서구 프로그램을 한 화면에 혼합하지 않습니다.
- `services/institution_dialogue.py`는 `institution_session`에 기관·사이트·회원 여부(이용자 자기신고)·단계·의도 기록을 저장합니다. 기존 `dialog`·추천 `turns`는 별개로 보존하며 신청 발화를 검색 함수에 보내지 않습니다. 계정·DB·파일 저장은 추가하지 않습니다.
- PR #16의 단계 이동 범위 제한을 `application_helper.advance_step`으로 공통화해 기관/기존 프로그램 도우미가 재사용합니다. 기존 공통 CSS, 음성 API, Gemini 클라이언트·응답 검증·오류 분류도 재사용합니다. 모델·Secrets·SDK·공식 활동 JSON은 변경하지 않습니다.

## 6단계와 자격

| 단계 | 안내 | 단계에 표시하는 검증 수준 |
|---|---|---|
| 1 | 복지관 회원인지 먼저 선택. 비회원이면 방문 회원등록 안내 | 실제 공개 웹페이지에서 확인(수집본이라는 한계는 별도 명시) |
| 2 | 이음 AI의 큰 링크로 공식 신청 사이트 열기 | 실제 공개 웹페이지에서 확인 |
| 3 | 기존 복지관 회원의 온라인 아이디 만들기/본인인증/로그인 구분 | 실제 공개 웹페이지에서 확인. 인증 이후 미확인 |
| 4 | 수강신청 및 결제 메뉴 | 로그인 이후 미확인. 이름·절차는 공개 메뉴와 2025 안내문 근거 |
| 5 | 현재 모집 안내를 직접 확인한 뒤 과목명·신청하기 | 로그인 이후 미확인. 2025 절차 참고이며 현재 강좌·비용·접수 가능 여부 미확인 |
| 6 | 나의 신청프로그램에서 실제 신청/추첨/대기/수납 확인 | 로그인 이후 미확인. 신청 완료나 수강 확정을 이음 AI가 확인하지 않음 |

신규 데이터는 `data/institutions/seongsan.json`이며 단계별 institution_id/site_id/step_id, 제목, 행동, 메뉴명, 공식 URL, 근거, 확인일, 검증 수준, 이미지/화살표, 선행 조건을 저장합니다. 현재 프로그램 목록은 빈 배열, 모집 상태는 unknown입니다. 단계 1·2의 버튼은 이음 AI 내부 행동이므로 공식 사이트 버튼명으로 표시하지 않습니다.

비회원/회원 여부 미확인 상태의 ‘다음’은 1단계를 벗어나지 못합니다. ‘기존 회원’ 선택은 자기신고이며 인증 성공이 아닙니다. 온라인 아이디 만들기가 복지관 회원등록을 대신하지 않습니다. 방문 회원등록의 현재 준비물·창구·접수 시간은 확인 필요로 두고, 전화는 신청 가능 전화가 아닌 기관 문의로 표시합니다. 2025년 수납 방식/기한을 현재 결제 절차로 단정하지 않습니다.

## AI·개인정보·모바일

Gemini는 현재 단계와 질문에서 허용된 의도 enum 하나만 추출합니다. 자유 답변·프로그램·버튼·URL·가격·모집일을 반환할 수 없도록 스키마와 검증을 제한합니다. 실제 안내 문장은 검증된 JSON/고정 규칙만 사용합니다. 명확한 다음/이전/초기화/회원 선언은 규칙으로 처리합니다. Gemini가 회원 자격을 생성하거나 명확한 막힘 요청을 단계 이동으로 덮어쓸 수 없습니다. 실패 시 안전한 진단 코드와 기본 안내를 유지합니다. 실제 API 키가 없어 이번 실제 연결 성공/실패 원인은 확인하지 않았습니다.

질문 원문은 신청 상태 이력에 남기지 않고 의도와 단계만 저장합니다. 일부 인증번호/주민번호/비밀번호 패턴은 Gemini 전송과 의도 이력 기록 전에 차단합니다. 음성은 내용 인식을 위해 기존 OpenAI STT에 먼저 전송되므로 인증정보를 말하거나 입력하지 않아야 합니다. 음성 인식문은 수정용으로 현재 세션에만 남을 수 있으며 영구 저장하지 않습니다. 음성/STT는 기존 OpenAI API를 사용하며 Gemini와 별도 키·비용이 필요합니다. 사용자에게 인증정보를 입력하도록 요구하지 않습니다. 강서구 음성 모듈도 보존했습니다.

현재 단계만 한 패널로 바뀌므로 `ui/institution_scroll.js`가 앱이 소유한 단계 앵커 ID 변경 때 안내 시작으로 스크롤합니다. 같은 ID의 rerun에는 이동하지 않고, 수동 wheel/touch가 있으면 따라가기를 중지합니다. 기존 채팅 스크롤 파일은 보존합니다. `.stMain`/위젯 접근성 선택자를 쓰는 기존 스타일·스크립트는 Streamlit 버전 변경 시 재검증이 필요합니다. 새 스크롤 스크립트는 외부 사이트 DOM을 읽거나 조작하지 않습니다.

## 검증과 남은 범위

자동 테스트는 기본 진입/회원 게이트/현재 단계 도움/다음·이전/초기화/AI 모의 성공·실패/환각 거부/인증정보 차단/이미지 없음/상태 미확인/강서구 왕복을 검사합니다. 기존 자동 테스트는 보존한 `gangseo_app.py`를 대상으로 실행하도록 경로만 변경했고, 기본 진입은 새 AppTest가 따로 검사합니다. 브라우저도 새 기관 기본 화면과 기존 강서구 회귀 화면을 분리해 실행합니다.

실제 Gemini/OpenAI API, Streamlit Community Cloud, iPad/iPhone Safari·Android 실기기, 공식 사이트 로그인 이후 화면·인증·신청·결제는 미검증입니다. 기관 공개 페이지 최신 캡처와 허용 범위를 확인하고, 실제 키로 의도 분류 및 실제 모바일 동작을 점검하는 후속 작업이 필요합니다. 현재 MVP는 실제 신청 결과를 보장하는 자동 신청 서비스가 아닙니다.


### 실행 결과 (2026-11-10)

- Python 자동 테스트 **186개 통과**: 기존 173개 + 새 기관 시나리오 13개. 신규 기본 앱 시작/재실행/기관 전환까지 AppTest로 검사했습니다.
- 모바일 Chromium **47개 흐름 통과**: 성산 기본/모의 Gemini 6개(320/390/768px), 기존 강서구 41개. 회원 게이트, 다음/이전/막힘/로그인 문제, 이미지 없음, 상태 미확인, 공식 링크, 실패 시 기본 안내, 왕복 상태 보존을 포함합니다.
- 모든 공식 강서구 카드 10건, 날짜·KeyError·추천 순서·인접 동의와 기존 모의 STT/TTS 흐름도 통과했습니다.
- 초기 새 스크롤 검사에서 시작 위치 이동 실패를 발견해 전용 제어로 수정했습니다. 브라우저의 단계 갱신/초기 CSS 완료 대기를 보강한 최종 6개 흐름은 통과했습니다.
- Python 문법 검사와 git diff --check 통과. 실제 API·Cloud·Safari·공식 사이트 로그인 이후 과정의 성공을 의미하지 않습니다.
