# 세션 기반 개인화 추천

## 구조와 재사용

기존 Gemini `FIELDS`/JSON 검증, `anchor_request`, `handle_turn`, `recommend`, 단일 `score_program`/`prepare_view`, 공통 카드·선택 버튼을 재사용합니다. 모델·Secrets·음성 SDK·공식 JSON 10건은 변경하지 않습니다. 신규 `personalization.py`는 대화 세션의 조건 모드와 사실 기반 설명만 담당합니다. 사용자 계정·파일·DB 저장을 추가하지 않습니다. 나이·거주지는 직접 발화한 경우만 추출하며 검색 지역을 거주지로 바꾸지 않습니다. ‘집에만’으로 건강 상태나 사회관계 목적을 추정하지 않습니다.

## 필수 조건과 선호

- 나이·거주 자격과 명시적인 지역·활동 조건은 기존 검증을 유지합니다.
- ‘오후가 좋아요’, ‘무료였으면 좋겠어요’는 선호입니다. 일치 자료에만 가산하며 불일치·정보 부족을 설명합니다.
- ‘오후로 찾아줘’, ‘무료로 찾아줘’, ‘꼭/반드시’는 필수입니다. 예산 단위의 임의 환산, 유료를 무료처럼 표시하지 않습니다.
- 새 시간·예산 발화가 해당 모드만 갱신하며 다른 조건은 유지합니다. ‘시간은 상관없어요’는 시간·모드를 해제합니다.
- ‘수영 말고 다른 운동’은 이전 종류·태그·초보 필터를 해제하고 거절한 종류는 아이디어에서 제외합니다. 지역·나이·시간·예산·명시한 목적은 유지합니다. 나중에 수영을 명시적으로 요청하면 제외를 해제합니다.
- ‘처음부터 다시’는 조건·모드·제외 목록을 초기화합니다. 세션의 대화 정보는 서버 영구 저장하지 않습니다(호스팅 운영 로그·브라우저 세션 보존 정책까지 보장한다는 뜻은 아닙니다).

## 정렬과 설명

직접 일치 300 / 유사 200 / 다른 대안 100을 기준으로 기존 목적·움직임·지역·대상·접수 상태를 사용합니다. 시간 선호는 공식 `time_slots` 일치에 +6, 예산 선호는 확인된 비용·단위가 맞을 때 +4입니다. 가중치 합계로 관련성 단계를 뒤집지 않습니다. 나이 자체, 추측한 건강·거리·접근성·실제 강도에는 점수를 주지 않습니다. 기존 일반 강도·이동 부담 점수도 제거했습니다. 나이는 공식 참여 자격 검증에만 사용합니다. 접수 가능 결과와 마감·미확인 참고 자료는 구분하며 마감 자료를 신청 가능한 결과로 승격하지 않습니다.

추천 이유는 Python 고정 문구와 공식 자료로만 만들며 Gemini가 시설·가격·일정을 생성하지 않습니다. 걷기→슬로우조깅은 보행 중심 유사 활동, 파크골프는 다른 대안입니다. 개인화 추가 설명은 지역 일치, 확인된 시간·비용, 미확인 강도·이동 편의만 다룹니다. 실제 건강 적합성이나 효과를 보장하지 않습니다. 카드 안에 이유를 한 번만 표시하고 공식 상태·핵심 정보를 이어 표시합니다.

## 질문과 범위

지역 없는 포괄적인 운동 요청은 강도 선호를 하나 묻고(건너뛰기 가능), 다음 지역 하나를 묻습니다. 지역이 이미 있으면 공식 자료를 먼저 추천합니다. 일반 아이디어를 명시하면 지역 없이도 아이디어를 볼 수 있습니다. ‘근처’의 위치는 추측하지 않습니다. 인접 지역 요청은 동의를 확인하고 저장된 인접 자료만 검색합니다. 현재 인접 자료가 없어 강서구 결과를 신규 결과로 재사용하지 않습니다. 실시간 웹 검색·추가 데이터·예약·지도·계정은 구현하지 않았습니다.

## 검증 범위

자동 테스트와 로컬 Streamlit AppTest, 320/390/768px Chromium 뷰포트 검사를 사용합니다. Gemini/OpenAI는 모의 응답 및 실패 테스트이며 실제 호출·Streamlit Community Cloud·iPad/iPhone Safari·Android 실기기 검증은 하지 않았습니다. 강도·접근성이 기록된 공식 자료 확장 및 실제 키로 조건 추출 품질을 평가하는 후속 작업이 필요합니다.

재현 명령: `python -m unittest discover -s tests`, `node tests/browser_personalization.cjs`. 기존 브라우저 검사는 `browser_smoke`, `browser_alternatives`, `browser_readable_details`, `browser_card_contract`, `browser_trusted_flow` 스크립트를 사용합니다. 로컬 앱 18502, 모의 API 18503/앱 18504, 카드 갤러리 18506이 필요하며, 읽기 전용 홈을 쓰는 테스트 환경에서는 Streamlit에 `--browser.gatherUsageStats=false`를 지정합니다. 브라우저 병렬 실행과 3초 제한 AppTest의 자원 경합을 피하도록 전체 단위 검사는 별도로 실행합니다.

2026-11-10 실행 결과: 전체 Python 자동 테스트 **149개 통과**(기존 137개를 새 대화 흐름에 맞게 갱신, 개인화 12개 추가). Chromium **35개 흐름 통과**(기존 32개 + 개인화 3개 화면 폭). 모든 공식 카드 10건, 날짜/KeyError 방어, 걷기 첫 선택=슬로우조깅, 선택 직후 상세/스크롤, 인접 자료 없음/중복 방지, 모의 Gemini 오류와 음성 실패 후 텍스트 유지까지 포함합니다. 병렬 검사 중 AppTest 한 건의 3초 제한 초과가 있었으며 재실행한 전체 149개는 통과했습니다. 최초 로컬 통계 설정의 홈 쓰기 오류는 테스트 서버의 통계 수집을 끄고 재검사했습니다. 실제 API·Cloud·Safari 성공을 의미하지 않습니다. 신규 공식 데이터는 추가하지 않았습니다.
