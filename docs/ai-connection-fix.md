# AI 연결 진단·대체 검색과 입력창 정렬 수정

> 이 문서는 OpenAI 질문 이해를 사용하던 PR #5 당시 기록이다. 최신 질문 이해 공급자·설정은 [Gemini 전환 안내](gemini-setup.md)를 따른다.

확인일: 2026-11-09 (한국 시간). PR #4가 병합된 main `ce8edc4`에서 `fix/ai-fallback-chat-input` 생성.
사용자가 Community Cloud에서 확인한 오류를 바탕으로 코드와 공식 문서를 점검했다. 배포 서버의 Secrets·결제·모델 권한·실패 응답은 직접 열람하지 않았다.

## 확인된 사실과 미확인 원인

- 기존 `services/ai.py`는 인증·한도·모델/옵션·연결 오류 및 JSON 파싱 실패를 모두 같은 메시지로 가렸다. 따라서 사용자가 본 문구만으로 실제 실패 유형을 알 수 없다.
- 기존 `handle_turn`은 AIError 때 바로 반환해 공식 데이터 검색도 중단했다. 키워드 검색 모듈과 공식 데이터 10건은 이미 있었으나 실패 시 연결하지 않았다.
- 기본 `gpt-5.4-mini-2026-03-17`은 [공식 모델 페이지](https://developers.openai.com/api/docs/models/gpt-5.4-mini)에 실제 스냅샷으로 명시된다. Responses·Structured Outputs 및 reasoning none/low 등을 지원한다. 모델 ID가 잘못됐다고 확정할 근거가 없으므로 기본값을 유지했다. 배포 Secrets/환경변수의 OPENAI_MODEL이 이를 덮어쓸 수 있고 해당 프로젝트의 접근 권한은 별개다.
- [공식 구조화 출력 문서](https://developers.openai.com/api/docs/guides/structured-outputs)의 Responses `text.format` 구조와 비교했다. 현재 스키마는 object 루트, 전체 required, additionalProperties=false, nullable 필드를 사용한다. 로컬 JSON Schema 유효성과 정상 응답 계약을 검증했다. 기본 비미세조정 모델에서 현재 길이/숫자/배열 제약이 원천적으로 미지원이라는 근거는 찾지 못했다. 실제 서버의 스키마 수락 여부는 실호출로 검증하지 않았다. 미세조정 모델로 변경하면 별도 제약을 확인해야 한다.
- [공식 SDK v3.46.0 릴리스](https://github.com/openai/openai-python/releases/tag/v3.46.0)를 확인했고 설치된 동일 버전에서 예외 타입과 실제 HTTP 전송 인터페이스를 점검했다. 이 SDK는 httpx2를 사용한다. 기존 패키지 버전을 유지했다.
- 과거 20초 timeout, reasoning low와 출력 2,000토큰이 실제 실패 원인이었는지는 모른다. 인증 실패, 결제/사용 한도, 모델 접근·옵션, 네트워크/지연, 불완전/거절/잘못된 응답 모두 가능하며 새로운 진단 코드로 구분해야 한다.

## 안전한 진단과 요청 설정

[공식 오류 문서](https://developers.openai.com/api/docs/guides/error-codes)와 설치 SDK의 예외 타입에 맞춰 분류한다.

| 고정 코드 | 의미 |
| --- | --- |
| key_missing / configuration | 키 없음 / SDK·서버 설정 구성 실패 |
| authentication / permission | 인증 거부 / 권한 거부 |
| quota / rate_limit | 결제 또는 사용 한도 코드 / 요청 속도 한도 |
| model_access | 모델 또는 API 경로가 없거나 접근 불가. 404만으로 모델 오타라고 단정하지 않음 |
| request_schema / request_parameter / request | 스키마 거부 / 옵션 거부 / 그 외 요청 거부 |
| timeout / connection / service | 대기 시간 초과 / 연결 실패 / 서비스 오류 |
| output_limit / incomplete / refused | 출력 한도 / 불완전 응답 / 거절 |
| response_format / unknown | JSON·필드 검증 실패 / 분류 불가 |

SDK 예외의 타입·HTTP 상태와 허용 목록의 오류 코드만 보고 고정 코드로 변환한다. 예외 본문·원문·동적 메시지·키·요청 ID·질문·음성·URL을 진단에 보관하거나 출력하지 않는다. 앱에 원문 로그를 추가하지 않았고 SDK/HTTP 전송의 debug/info 로그를 억제한다. 공개 로그에 원문 오류를 붙여 넣지 않는다.

SDK timeout은 30초, 자동 재시도는 0회다. timeout은 SDK/전송 단계 제한이며 정확히 30초의 전체 실행 마감 시간을 보장하지 않는다. 확인된 GPT-5.4 mini 별칭·스냅샷에서만 `reasoning.effort=none`을 명시한다. 다른 모델에 gpt-5/gpt-6 접두어만 보고 옵션을 붙이지 않는다. 출력 한도 2,000토큰과 store=false, strict 스키마·로컬 검증은 유지한다. 출력 한도/거절/파싱 실패는 서로 구분한다.

## 실패 후 공식 검색

API 오류 또는 응답 검증 실패 시 기존 `basic_extract`로 같은 질문을 한 번 해석하고 `recommend`로 최대 3개 공식 활동을 찾는다. 이전 조건과 대화는 보존하고 명시적으로 인식한 새 조건만 갱신한다. 원래 상태 객체를 변경하지 않는다.

화면에는 기본 키워드 검색임을 알리는 안내와 ‘연결 상태 확인’ 펼침 메뉴를 표시한다. 음성안내에도 대체 검색이라는 안내를 포함한다. ‘어르신’이라는 표현으로 나이·참여 자격을 생성하지 않는다. 활동은 공식 JSON에서만 읽고 비용/신청 가능 여부를 보장하지 않는다. 인식할 키워드가 없으면 이전 카드를 새 추천처럼 재사용하지 않고 활동을 다시 묻는다. 직접 조건 검색으로 전환하면 이전 오류 안내를 지운다.

사용자 질문은 말풍선과 대화 이력에 남는다. 새 후속 질문은 정상 AI 호출을 다시 시도하며 성공하면 이전 오류 표시를 지운다. 공식 일정의 `~` 문자가 Markdown 취소선으로 해석되지 않도록 카드 표시에서 이스케이프한다. 데이터 원문은 바꾸지 않는다.

## 입력창 변경

- 하나의 둥근 테두리 안에 글 입력과 오른쪽 64×64px 주 아이콘 버튼을 배치했다. 빈 입력에서는 마이크, 글 입력 시에는 같은 위치의 전송 버튼을 사용한다.
- 글 입력 중 음성 복귀는 원래 native 마이크를 44×44px 보조 아이콘으로 재사용한다. 누르면 글을 비우고 음성 입력으로 돌아가며 즉시 녹음하지 않는다.
- 기존 `#ieum-voice-back` 추가 노드를 만들던 코드를 삭제했다. React가 관리하는 영역에 별도 버튼을 삽입하거나 재배치하지 않는다. native 버튼의 캡처 단계에서 초안 여부를 확인하고, 한국어 접근성 이름과 data 속성만 보정한다.
- 녹음 중 같은 영역 안에 ‘듣고 있어요’, ‘말하기 끝내기’와 취소를 유지한다. STT→AI/기본검색, TTS, 수정·다시 말하기, 단일 대화 흐름을 유지한다. 침묵 자동 종료는 추가하지 않았다.
- 기본 위젯의 내부 선택자·레이아웃, :has, DOM 속성/이벤트 보정에 의존하므로 Streamlit 버전 변경 시 회귀 검증이 필요하다. 고정 1.66.1을 유지했다. iPad의 실제 원인이 이것이었다고 단정하지 않으며 실제 Safari 재검증이 필요하다.

## 검증 범위

- unittest **62개 통과**. 기존 항목을 대체 검색 동작에 맞게 갱신하고 실제 SDK 예외 객체로 인증·권한·한도·모델·옵션·timeout·연결·서비스 오류, 응답 형식·거절·불완전 응답, 요청 계약·스키마와 사용자 제보 질문의 대체 검색을 검사했다. 제공자 오류에 비밀 대체 문자열을 넣어 진단과 화면 상태에 남지 않는지 확인했다.
- Chromium/Playwright **10개 흐름**: 320/390/768px의 입력창·주 버튼 위치 일치·테두리 안 배치·가로 넘침·추가 마이크 노드 없음, 대화/신청 안내/작아진 화면, 합성 마이크/STT/검색/TTS/수정·재녹음, 권한/장치/미지원 및 재생 거부 후 글 대화, 파일 업로드, 모의 HTTP 401 뒤 안전한 진단·공식 대체 검색·후속 대화.
- 모의 서버는 제보 질문에 **의도적으로** 401을 반환한다. 이는 실제 배포 오류가 401이라는 뜻이 아니다. STT는 고정 문장, TTS는 시험용 톤이다.
- 실제 OpenAI 호출 **미실시**: 이 개발 환경에는 키가 없고 api.openai.com 네트워크 허용도 없다. 실제 계정의 인증·결제·한도·모델 접근, 한국어 음성 품질은 확인하지 않았다.
- 실제 iPad/iPhone Safari, Android Chrome, VoiceOver/TalkBack, Community Cloud 수정본 배포는 **미검증**이다. Chromium 모바일 크기·축소 viewport 검사는 실기기 키보드 검증을 대신하지 않는다.

## Community Cloud에서 다음에 확인할 것

PR을 검토·병합하고 재배포한 후 같은 질문으로 다시 검색한다. 실패 시 ‘연결 상태 확인’의 **고정 진단 코드**를 확인한다. 원본 API 오류나 키를 공개하지 않는다.

Secrets의 OPENAI_API_KEY와 OPENAI_MODEL(선택)을 확인한다. 모델을 명시한다면 `gpt-5.4-mini-2026-03-17`이며, 환경변수가 Secrets보다 우선한다. 빈 값/공백만 있는 모델은 기본값을 사용한다. 모의 테스트용 OPENAI_BASE_URL은 배포에 설정하지 않는다. 인증이면 키와 프로젝트, quota면 API 결제/한도, model_access면 모델·프로젝트 권한·서버 주소를 점검한다. ChatGPT 구독과 API 사용 설정은 별도로 확인한다.

iPad에서 빈 입력→마이크, 글 입력→전송, 보조 마이크 복귀, 녹음 종료·STT·답변, 수정·재녹음, 직접 듣기·중지, 키보드 열기와 회전을 확인한다. 자동 음성 재생 성공은 가정하지 않는다.
